## Corrections that apply

- **§C14.** Derivation emits `tierSpan = 1` + `xpToNextRank = 0` at top tier. UI MUST branch on `nextRank === null` and force `pct = 100` BEFORE the division. Hall of Fame floor is `min: 5000`, so `xp = 50000` yields `xpInTier = 45000` and a naive `xpInTier / tierSpan` overshoots. Mirror canon `progress.jsx:263–265`.
- **§C10.** Payload `progress` is `.optional()`. Wrapper (chunk 39) returns `null` when absent. Component therefore accepts `progress` as **required** non-null; documented in JSDoc + prop type.
- **Canon §12 (shared tooltip handler contract).** `XPScoreboard` accepts `onPressHint?: () => void` (OPTIONAL) on both mobile + web twins. Mobile composition (chunk 39 `ProfileStats`) owns tooltip state and passes the opener. SSR composition (chunk 41 `ProfileStatsWeb`) passes `undefined` so the `?` renders as a non-interactive `<span>` / `<View>` with no handler — no modal exists on SSR. This resolves the skeleton MAJOR drift (chunks 36/39/41) cited in the review: a single optional-handler contract serves both surfaces without an extra `tooltipMode` prop.
- **Canon §13 (UI package dep).** `expo-linear-gradient` becomes a `@ccc/ui` runtime dep. Adds to `packages/ui/package.json`; lockfile regenerated by `pnpm install`. Both files belong to "Files touched" for this chunk.

Outline content not applicable: §C1–C9, §C11–C13 (server / route / admin). §299 "animation" — deferred to Phase 2D (skeleton open-Q #1 default = hard-set).

Width formula (§C14):

```ts
const isTopTier = progress.nextRank === null;
const pct = isTopTier
  ? 100
  : Math.max(0, Math.min(100, Math.round((progress.xpInTier / progress.tierSpan) * 100)));
const caption = isTopTier
  ? 'Topo do ranking'
  : `${progress.xpToNextRank.toLocaleString('pt-BR')} → ${progress.nextRank}`;
```

Prop interface (shared shape — mobile + web twins both use this contract per canon §12):

```ts
import type { GarageProgress } from '@ccc/shared/garage-progress';

export interface XPScoreboardProps {
  /** Server-derived progress (chunk 24). MUST be non-null — wrapper short-circuits when missing. */
  progress: GarageProgress;
  /**
   * Tap handler for the `?` button. OPTIONAL (canon §12).
   * - Mobile composition (chunk 39 ProfileStats) passes the tooltip opener.
   * - SSR composition (chunk 41 ProfileStatsWeb) passes undefined → `?` renders
   *   static + non-interactive (no Pressable on mobile, no <button> on web).
   */
  onPressHint?: () => void;
  /** Used by tests + dispatch tracking. */
  testID?: string;
}
```

Mobile RN rendering rule for the `?` element:

- When `onPressHint` is a function → render a `<Pressable>` with `onPress={onPressHint}`, 8px `hitSlop`, `accessibilityRole="button"`, `testID` suffix `-hint`.
- When `onPressHint` is `undefined` → render a `<View>` (or `<Text>`) with `accessibilityRole="text"`, no `onPress`, no `testID` (or `testID` suffix `-hint-static`). No tap target.
